## 何を見るか（この順に）

### 1. ★ 答えが合っているか（最優先）

**ドリルは乱数で問題を作ります。**だから 1 回見て合っていても足りません。

- **`answer` を出す式と、`question` が言っている内容が一致しているか**
- **`choices`（誤答）の作り方に、答えと同じ値が混ざる余地がないか**
- **★ 乱数の端で壊れないか。**最小値・最大値・境目を入れて確かめること。
  **実際に「誤答が 0 になる」ドリルを 1 つ出しました**（丸めで 0 になる式だった）
- **単位が混ざっていないか。**MPa と kPa、L と m³、kg と t、℃ と K
- **ゲージ圧力と絶対圧力を取り違えていないか。**
  **法令の「圧力」はゲージ圧力、状態方程式に入れるのは絶対圧力**

### 2. ★ 電卓の制約

**本番の電卓は四則計算と開平計算だけです**（受験案内書 Ⅲ-3-③）。
**対数・指数・三角関数は打てません。**

- **対数や指数を含む式を、値まで出させていないか**
- **開平で済む形になっているか**
- **途中の桁数が現実的か。**手で 10 桁を持ち回る問題になっていないか

### 3. 法令の値

- **法令由来の値は、`docs/primary-numbers.md` を経由しているか。台帳に無い値を書いていないか**
- **物性値（比重、分子量、爆発範囲など）は、台帳に一次資料がありません。**
  **決め打ちせず、問題文の中で与えているか**を見ること
- **★ 容器則は基準日版で確かめること**（`docs/primary-numbers.md` §0）

### 4. ウィジェット

- **入力の範囲。**負の数、0、極端に大きい値を入れたときに、
  **NaN・Infinity・「-0」・空文字が画面に出ないか**
- **結論が変わる境目で、表示が正しく切り替わるか**
- **★ 値を決め打ちしていないか。**
  爆発範囲や圧縮係数のように台帳に一次資料が無いものは、
  **ユーザーに入れさせる作りになっているか**
- **「このアプリが断定してよい範囲」を越えていないか。**
  合否の判定、法令の適用の断定はしない

### 5. 画面の文言

- **`docs/public-questions.md` §3 のとおり、計算問題は多くありません**
  （令和 7 年度で化学 15 問中 4 問、機械 15 問中 1 問）。
  **「学識は計算が中心」と読める書き方になっていないか**
- **合格基準を「60 パーセント以上」と書いていないか**（この試験は「程度」）
- **前のアプリの試験名が残っていないか**

### 6. 科目の割り当て

- **`gk-`（化学）と `gm-`（機械）を取り違えていないか**
- **ドリルの配分**（化学を厚く、機械を薄く）が `docs/public-questions.md` §3 と合っているか

## 報告の形

**指摘は、次の形で 1 件ずつ書いてください。**

```
### 【重さ】 ドリル ID / ウィジェット ID — 一行の要約

- **いまの作り**：
- **何が問題か**：（★ 壊れる入力があるなら、その値を具体的に書く）
- **正しくは**：
- **根拠**：（条・項・号、またはファイル名と箇所）
```

**重さは 3 段階。**

| 重さ | 何か |
| --- | --- |
| **重** | **答えが違う。**誤答に正解と同じ値が出る／電卓で解けない／NaN が画面に出る |
| **中** | 解けるが、条件が足りず一意に決まらない。単位の書き方が紛らわしい |
| **軽** | 言い回し、桁数、配分 |

**最後に、次の 4 つを必ず書いてください。**

1. **全ドリルについて、乱数の端まで含めて答えを確かめたか**（確かめていないものは挙げる）
2. **確かめたが食い違いが無かった項目**
3. **資料からは確かめられなかった項目**
4. **★ あなたが自信を持てない指摘**

**4 が空の報告は受け付けません。**
